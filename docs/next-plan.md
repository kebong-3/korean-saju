# 사주냥이 다음 개선 계획 (2026-11-27)

이번에 한 것: 화면 스크립트 14개로 분리, 사용량 제한, 보안 헤더(CSP 등), 다른 사이트 요청 차단, 운영자 전용 점검, 지도 열쇠 헤더화, 서비스 워커 캐시 우선, 재방문 즉시 열기.
아래는 그다음 할 일이다. 각 줄의 **[사용자]** 는 대시보드·계정 주인만 할 수 있는 일이다.

## 1. 유입 논리 — 지금 가장 약한 곳

지금 구조는 "검색·공유로 들어옴 → 생일 입력 → 첫 감명 카드 → 홈"이다. 문제는 **들어온 이유가 입력 뒤에 사라진다**는 점이다.
"을사일주 성격"을 검색해 온 사람도, 친구 스토리 카드를 보고 온 사람도 똑같은 홈을 본다.

| 할 일 | 내용 | 기대 |
|---|---|---|
| 들어온 이유 이어 주기 | 안내 페이지 CTA에 `?from=ilju&k=을사` 같은 꼬리표 → 가입 직후 그 내용(내 일주 카드, 내 신살 표, 2027 카드)을 첫 화면으로 | 검색 유입의 가입·첫 화면 이탈 감소 |
| 생일 넣기 전에 맛보기 | 첫 화면에 "오늘의 패" 한 장이나 샘플 냥이 카드를 먼저 보여 주고 생일은 그다음 | 첫 화면 이탈 감소(지금은 폼부터 보임) |
| 검색 페이지 확장 | 띠별 2027 운세 12쪽, 일간끼리 궁합 100쪽(갑목×을목 …), 월별 운세 흐름 12쪽 | 검색어 범위 3배 |
| 페이지마다 공유 그림 | 안내 페이지별 og 이미지(일주 냥이 그림) | 카톡·인스타 링크 클릭률 |
| 공유 꼬리표 | 스토리 카드·지도 링크에 `from=story` / `from=map` → 어떤 공유가 사람을 데려오는지 숫자로 | 공유 기능 우선순위 판단 |
| 카카오 공유 | 카카오 SDK로 그림 카드 공유(앱 키 필요) **[사용자: 카카오 개발자 앱 등록]** | 20대 여성 주 공유 채널 |
| 검색 등록 | Google Search Console·네이버 서치어드바이저에 sitemap 제출 **[사용자]** | 99쪽이 실제로 검색에 뜨기 시작 |

## 2. 서비스 — 다시 오게 만드는 고리

- **알림 권유 시점**: 지금은 메뉴 안에 있다. 첫 감명 카드를 다 본 직후 "내일 아침 7시에 오늘의 패 보내 줄까?"로 한 번 묻는다.
- **연속 출석 보상 보이기**: 출석·도감은 있는데 홈에서 잘 안 보인다. 홈 머리에 "3일째 🔥 · 다음 옷까지 2일"처럼 한 줄.
- **약속 → 다음 날 확인**은 상담에서만 생긴다. 오늘의 패·정원에서도 "오늘 한 가지"를 약속으로 만들 수 있게.
- **측정 깔때기**: 들어옴 → 가입 → 첫 카드 끝 → 탭 2개 이상 → 다음 날 재방문. Web Analytics를 켜야 숫자가 쌓인다 **[사용자]**.

## 3. 화면(UI)

- 홈이 길다(카드 8종 이상). "지금 나에게" 한 장 + 오늘 운세 + 바로가기 4개까지만 첫 화면, 나머지는 접기.
- 손가락 크기: 일부 칩·용어 버튼이 44px보다 작다. 만세력 칸, 용어 칩, 닫기 버튼 점검.
- 밤 모드 대비: 회색 작은 글씨(설명문) 대비가 4.5:1 아래인 곳이 남아 있다.
- 실제 폰 확인: iPhone Safari(특히 iOS 16)와 카톡 안 브라우저에서 첫 화면·스토리 저장·알림 **[사용자 폰 필요]**.

## 4. 성능

- **늦게 불러오기**: 파일을 나눠 놨으니 도감·정원·스토리·백업(play/records/look 일부)은 첫 화면 그린 뒤 불러오면 첫 다운로드가 약 30% 준다.
- **CSS 93KB**: 첫 화면용과 나머지로 나누기. 글꼴 3종(Jua·Gowun Dodum·Gaegu) 중 Gaegu는 카드에서만 쓰므로 늦게.
- **서버 첫 응답**: 파이썬 서버가 잠에서 깨는 데 1~3초. 재방문은 이번에 기기 캐시로 해결했고, 첫 방문은 계산 중 화면으로 가린다. 더 줄이려면 엔진 불러오기 시간을 재고 무거운 모듈을 필요할 때 불러오기.
